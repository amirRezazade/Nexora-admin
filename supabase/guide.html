دیتابیس را روی Supabase این‌طور بساز

لازم نیست SQL را از صفر بلدی. حساب می‌سازی، دو فایل را در SQL Editor اجرا می‌کنی، بعد جدول‌ها را با دیتای واقعی Nova می‌بینی. کل کار حدود ۱۵ دقیقه است.

۸ جدول + ۱ view ۲۸ محصول ۸۰ مشتری ۱۵۰ سفارش ۲۲۷ آیتم سفارش
۰ نقشه دیتابیس ۱ ساخت حساب و پروژه ۲ داشبورد را بشناس ۳ اجرای schema.sql ۴ ریختن دیتا ۵ چک کردن جدول‌ها ۶ تست API ۷ RLS یعنی چه

۰. اول بفهمیم چه چیزی می‌سازیم

Nova الان دیتایش را در حافظهٔ سرور Next نگه می‌دارد. ما همان مدل را به Postgres واقعی منتقل می‌کنیم. هر جعبه یک جدول است. فلش یعنی رابطه.

جدول واقعی

محصول، مشتری، سفارش… هر ردیف یک موجودیت است. بینشان کلید خارجی می‌گذاریم تا سفارش بدون مشتری ساخته نشود.

view انبار

inventory کپی جدا نیست. از روی stock محصول حساب می‌شود. اگر موجودی عوض شود، انبار هم عوض می‌شود.

۳. ساخت جدول‌ها با schema.sql

جدول‌های Nova ستون زیاد دارند. ساختن دستی‌شان خسته‌کننده و پرخطاست. یک اسکریپت همه را با رابطه می‌سازد.

  1. در سایدبار روی SQL Editor بزن.
  2. New query / New snippet.
  3. محتوای فایل nova/supabase/schema.sql را کامل کپی و در ادیتور پیست کن.
  4. پایین سمت راست (یا بالا) Run را بزن. میانبر معمولاً Ctrl + Enter است.
اگر موفق باشد پایین صفحه چیزی شبیه Success. No rows returned می‌بینی. بعد برو Table Editor. باید این اسم‌ها را ببینی: categories customers products coupons orders order_items reviews notifications و view به اسم inventory.
اگر خطا دیدی، کل متن خطا را کپی کن. معمولاً یعنی فقط بخشی از فایل پیست شده. schema.sql را از begin; تا commit; کامل اجرا کن.

این فایل چه کار می‌کند؟

قسمتمعنی ساده
create table productsجدول محصول با قیمت، موجودی، SKU
references categories(id)هر محصول باید به یک دستهٔ موجود وصل باشد
check (price > 0)قیمت صفر یا منفی ذخیره نمی‌شود
variants jsonbسایز/رنگ‌ها داخل یک ستون JSON
create view inventoryانبار از روی موجودی محصول محاسبه می‌شود
enable row level securityقفل پیش‌فرض جدول‌ها؛ سیاست‌های دمو دسترسی را باز می‌کنند

۴. ریختن دیتای Nova

جدول‌ها هنوز خالی‌اند. فایل seed.sql همان کاتالوگ Nova را وارد می‌کند (Nike Air Max 90، سفارش NV-13264 و بقیه).

  1. باز هم SQL Editor → New query (یک تب جدید، روی schema ننویس).
  2. کل فایل nova/supabase/seed.sql را پیست کن.
  3. Run.

این فایل حدود ۲۳۰ کیلوبایت است و چند ثانیه طول می‌کشد. Success یعنی دیتا نشسته.

ترتیب مهم است: اول schema.sql، بعد seed.sql. اگر seed را دوباره اجرا کنی، اول truncate می‌کند و دوباره همان دیتا را می‌ریزد. بی‌خطر است.

  3. برو orders و NV-13264 را باز کن: Bruno Moreno، وضعیت pending.

ج) چند کوئری برای فهمیدن دیتا

هر کدام را جدا Run کن:

-- محصولات کم‌موجود
select name, sku, stock, threshold
from products
where stock <= threshold
order by stock;
-- سفارش‌های باز
select id, customer_name, total, status
from orders
where status in ('pending','processing','shipped')
order by placed_at desc;
-- پرفروش‌ها از روی آیتم‌ها
select p.name, sum(i.quantity) as units, sum(i.total) as revenue
from order_items i
join products p on p.id = i.product_id
group by p.name
order by revenue desc
limit 8;

۶. تست API آمادهٔ Supabase

داشبورد جدید دیگر صفحهٔ Settings → API با نوشتهٔ anon ندارد. دو مقدار را این‌طور پیدا کن.

آسان‌ترین راه: دکمهٔ Connect

  1. بالای صفحهٔ پروژه، دکمهٔ Connect را بزن (معمولاً کنار Project Settings).
  2. تب App Frameworks یا React را باز کن.
  3. دو مقدار را کپی کن:
    • Project URL شبیه https://abcdefgh.supabase.co
    • Publishable key که با sb_publishable_ شروع می‌شود (در پروژه‌های قدیمی ممکن است هنوز anon / eyJ... باشد)

اگر Connect را ندیدی

چی می‌خواهیکجا
آدرس پروژه منوی چپ → Integrations → Data API
یا از URL مرورگر: اگر داشبورد این است supabase.com/dashboard/project/abcdefgh/... آدرس API می‌شود https://abcdefgh.supabase.co
کلید آیکون چرخ‌دنده پایین سایدبار → API Keys
تب API Keys / Publishable key
اگر نبود: تب Legacy API Keys و کلید anon
اگر دکمهٔ Create new API Keys دیدی، بزن و Publishable را بردار.

در ترمینال (آدرس و کلید را جایگزین کن):

curl "https://YOUR_PROJECT.supabase.co/rest/v1/products?select=id,name,sku,stock,status&order=name" \
  -H "apikey: YOUR_PUBLISHABLE_KEY" \
  -H "Authorization: Bearer YOUR_PUBLISHABLE_KEY"

فیلتر: status=eq.pending یعنی مساوی. اگر کلید جدید sb_publishable_ است و خطای Invalid JWT گرفتی، فقط هدر apikey را بفرست و Authorization را حذف کن.

کلید secret یا service_role را هیچ‌وقت در فرانت یا گیت نگذار. فقط Publishable / anon را بردار.
این قدم فقط برای تست است. اگر در Table Editor دیتا را می‌بینی، دیتابیس ساخته شده و لازم نیست همین الان curl بزنی.

۷. RLS یعنی چه؟ (کوتاه)

Row Level Security قفل ردیف‌های جدول است. در Supabase جدول جدید به‌صورت پیش‌فرض قفل است؛ اگر سیاست ننویسی، API خالی برمی‌گرداند — حتی اگر در Table Editor دیتا را ببینی.

داخل schema.sql برای هر جدول یک سیاست دمو گذاشتم: for all using (true) یعنی فعلاً خواندن و نوشتن برای کلید anon آزاد است. برای پورتفولیو کافی است. وقتی Auth واقعی وصل شد، این سیاست‌ها را تنگ‌تر می‌کنیم.

تا اینجا دیتابیس ساخته شده. اپ Nova هنوز به آن وصل نیست و همان API داخلی خودش را دارد. وصل کردن فرانت قدم بعدی است؛ اول همین را تا مرحلهٔ ۶ جلو ببر.
