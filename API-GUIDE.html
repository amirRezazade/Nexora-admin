Nova Store · API Reference

راهنمای کامل API برای ساخت از صفر

این سند قرارداد واقعی ادمین Nova است: مدل داده، احراز هویت، لیست‌ها، جزئیات، اعتبارسنجی، قوانین کسب‌وکار و شکل JSON که فرانت انتظار دارد. اگر از صفر می‌سازی، همین را پیاده کن.

پروژهٔ زنده: https://akqrnvrgsnofnhrhlxow.supabase.co · تاریخ مرجع داده: 2026-08-21

۰ معماری دو لایه ۱ احراز هویت ۲ قرارداد مشترک ۳ Enumها ۴ مدل‌های داده ۵ Products ۶ Categories ۷ Inventory ۸ Orders ۹ Customers ۱۰ Coupons ۱۱ Reviews ۱۲ Notifications ۱۳ Dashboard / Analytics ۱۴ Search ۱۵ Storage عکس ۱۶ قوانین کسب‌وکار ۱۷ چک‌لیست ساخت از صفر

۰. معماری

فرانت هیچ‌وقت مستقیم snake_case سوپابیس را مصرف نمی‌کند. یک لایهٔ API (در Nova: src/lib/sbApi.js) جدول‌ها را به camelCase تبدیل می‌کند.

لایهآدرسنقش
فرانت (قرارداد ادمین)/api/...camelCase، صفحه‌بندی، summary، خطاهای 422
سوپابیس RESThttps://PROJECT.supabase.co/rest/v1/...Postgres + RLS، snake_case
سوپابیس Auth.../auth/v1/...ورود، سشن، JWT
سوپابیس Storage.../storage/v1/object/public/product-images/...فایل عکس عمومی
اگر بک‌اند خودت را می‌نویسی (Express, Nest, Django…) همان قرارداد /api/... را پیاده کن. لازم نیست سوپابیس باشد.

۱. احراز هویت

ادمین است نه فروشگاه مشتری. نقش‌ها: admin | staff.

دمو

email: sarah@novastore.com
password: nova2026

ورود

POST /auth/v1/token?grant_type=password

{
  "email": "sarah@novastore.com",
  "password": "nova2026"
}

هدرها:

apikey: SUPABASE_ANON_OR_PUBLISHABLE_KEY
Content-Type: application/json

موفق: access_token, refresh_token, user.

خطاهای رایج: ایمیل تأییدنشده email_not_confirmed · رمز غلط.

درخواست‌های بعدی دیتا

apikey: KEY
Authorization: Bearer ACCESS_TOKEN

بدون توکن کاربر، بعد از RLS قفل، لیست‌ها خالی یا خطا می‌شوند.

۲. قرارداد مشترک لیست‌ها

همهٔ GETهای جدولی این queryها را می‌فهمند:

پارامترمعنی

sortنام فیلد camelCase
dirasc | desc
pageاز ۱
pageSizeپیش‌فرض ۱۰، حداکثر ۲۰۰
فیلترهاتکرار یا کاما: status=active یا status=active,draft · مقدار all یعنی بدون فیلتر

پاسخ لیست استاندارد

{
  "data": [ /* ردیف‌ها */ ],
  "total": 50,
  "page": 1,
  "pageSize": 10,
  "totalPages": 5

بعضی لیست‌ها فیلد اضافه دارند: summary, counts, all.

۱۰. Coupons

GET /api/coupons — جستجو code, description. فیلتر status, type.

POST

{
  "code": "WELCOME10",
  "type": "percentage",
  "value": 10,
  "minOrder": 50,
  "limit": 5000,
  "startsAt": "2025-01-01",
  "expiresAt": "2026-12-31",
  "status": "active",
  "appliesTo": "all",
  "scope": [],
  "description": ""
}

422: Coupon code is required. · تکراری · Discount value must be greater than 0. (جز free_shipping) · درصد > ۱۰۰ · Choose an expiration date.

کد را Uppercase ذخیره کن. usage شروع ۰. free_shipping → value=0.

PUT /api/coupons/:id · DELETE

اعمال روی سفارش (منطق، نه لزوماً endpoint جدا)

  1. status=active و امروز داخل startsAt…expiresAt
  2. subtotal ≥ minOrder
  3. اگر usage_limit دارد و usage ≥ limit → رد
  4. appliesTo=all روی کل سبد؛ categories فقط آیتم‌های آن دسته‌ها؛ products فقط آن productIdها در scope
  5. percentage: round(subtotal_eligible × value / 100, 2)
  6. fixed: min(value, حدود ۵۰٪ سبد در دیتای نمونه)
  7. free_shipping: shipping=0

۱۱. Reviews

"average": 4.4

average روی همهٔ ردیف‌های برگشتی قبل از فیلتر صفحه است (کل جدول).

PATCH /api/reviews/:id { "status": "published" }

بعد از تغییر publishedها: products.rating = round(avg, 1) و reviewCount = count فقط status=published. pending/hidden در ستارهٔ محصول نیایند.

آرایهٔ products.images را جداگانه PATCH کن. عکس اول primary=true.

۱۶. قوانین کسب‌وکار که باید پیاده کنی

  1. SKU یکتا، uppercase در ذخیره.
  2. price > 0. compareAt اگر هست > price.
  3. stock ≥ 0. stockStatus از روی stock با آستانه ۸.
  4. حذف دسته فقط اگر هیچ محصولی به آن وصل نباشد.
  5. امتیاز محصول فقط از review.status=published.
  6. totalSpent مشتری بدون cancelled/refunded.
  7. سفارش بدون مشتری ساخته نشود (FK).
  8. آیتم سفارش name/sku را snapshot کند؛ اگر محصول حذف شد خط سفارش نماند بدون نام.
  9. مالیات دمو ۱۹٪. ارز USD.
  10. name انگلیسی canonical است؛ nameFa برای UI فارسی.
  11. ریویوی مشتری ترجمه نشود.
  12. تاریخ KPI را با NOW ثابت دمو هم‌خط کن یا داده را نسبت به امروز بساز.

۱۷. چک‌لیست ساخت از صفر

  1. جداول: categories, products, customers, orders, order_items, coupons, reviews, notifications, profiles.
  2. view inventory.
  3. Auth ایمیل+رمز. کاربر ادمین.
  4. RLS: فقط authenticated + is_staff(). عکس Storage خواندنی عمومی، نوشتن staff.
  5. لایهٔ API با قرارداد همین سند (camelCase + pagination).
  6. فرانت: لیست‌ها با q/sort/page، جزئیات، CRUD محصول، bulk، گالری Swiper، ورود.
  7. تست: ورود سارا → GET products باید ۵۰ ردیف و عکس Court Sneaker را بدهد.
اگر فقط فرانت می‌سازی: همین URLها و JSONها را mock کن. اگر فقط بک‌اند می‌سازی: همین پاسخ‌ها را برگردان تا UI فعلی Nova بدون تغییر کار کند.
سوپابیس REST خام snake_case است (category_id نه categoryId). فرانت Nova camelCase می‌خواهد. یا map کن یا از ابتدا camel بده.
